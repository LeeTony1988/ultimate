Switch the window between the user's registered projects from the title bar, with each project's state and a full-page switch because every project is its own origin.

The chip in `titlebar.project` lists `host.projects()` newest-opened first; the current project is marked, a running one is a real `<a href>` to its URL (so new-tab and middle-click work), and a stopped one is a button that starts its host with this checkout's `bin/ultimate.ts` and navigates when its API answers. The root is shortened in the row's tooltip, as is the conversation count; a stopped row also names `ultimate <root>` for starting by hand.

`list` (`null`) returns `{ root, name, current, running?: { url }, openedAt?, conversationCount }[]`, shaped on the server from `host.projects()`. It deliberately keeps `home` and `pid` off the wire. Homes without a `project.json` root are skipped: they cannot be opened or identified. `open` (`{ root }`) is user-only, refuses any root that is not in that list, never starts the current project, and returns `{ url }` for the project's live host, starting it first when needed.

Starting matters because a stopped project has no host and no origin to link to. The launcher already solves the hard parts: `acquireLock` arbitrates two hosts racing for the same home, and without an explicit port the supervisor moves up from 4747 and writes the port it actually bound into `ultimate.lock` after its proxy listens. `open` spawns `bin/ultimate.ts <root> --no-open` detached, with `ULTIMATE_HOME` set to the target's registered home and the asking host's `ULTIMATE_HOME`/`ULTIMATE_PORT`/`ULTIMATE_USER_HOME`/`ULTIMATE_PROJECT` identity cleared, then polls that lock and `/api/models` for at most 30 s. One in-flight start is shared per home, so a double click or second tab cannot spawn a second host. If the child exits or the deadline passes, the action throws a message naming the root and `ultimate <root>`; the row stays `not running` and shows the error. The failure mode left in place is that a host which starts but never answers `/api/models` within 30 s is reported as failed even though its process may still be up; run the command in the tooltip to see its `supervisor.log`.

P0 only: this does not change isolation, storage, process boundaries, the `~/.ultimate` layout, or user-level secrets. Workspace switching (P1), a resource budget (P2) and registry cleanup (P3) are not part of it.

## 三分钟版本

Ultimate 不会在对话中途突然重写自己的代码。它把"修改自己"拆成六层，从最便宜的记忆，到最贵的核心代码和上游更新。每一层只有一个写入口、一种生效方式和一种回滚方式。

一次典型的自我改进长这样：

1. 你在对话里纠正了它一次，它把这条教训写进**项目记忆**；
2. 下一个分支启动时，从这份记忆的索引开始，而不是从零开始；
3. 它定期（或由你触发）进入 **Dream**：读历史、跑六个反思方向、写一份 journal、提出若干提案；
4. 你逐条批准或拒绝；批准的提案变成普通分支，走 review 和 lander；
5. 代码变更通过 lander 落地，重启后生效；下一次对话里，它知道自己换了一份代码。

关键点：**每一步都有闸门，每一步都可回滚。** Dream 自己不改代码，记忆写入只能由 @ultimate 做，代码变更必须走分支和审查。

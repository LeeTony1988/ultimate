## 三分钟版本

Agent 干活时，用户能看到的通常只有一段不断变长的聊天记录。它回答不了三个最基本的问题：现在卡在哪？为什么慢？是谁把这件事交给了谁？

两个 app 分别回答其中一类问题：

- **TaskScope** 看**任务**：一次 run 的任务图、关键路径、失败与重试、和上次相比的变化。
- **AgentLoom** 看**agent**：谁 spawn 了谁、消息怎么流动、每个 agent 花了多少 token、失败链的第一跳在哪。

它们不是两套独立系统，而是同一个内核的两种投影：都从同一套事件出发，归一化成统一模型，再画成不同的视图。共享的部分包括数据模型、适配器、SQLite 存储、图形基础组件；不同的只有视图和交互。

两条产品原则：

1. **本地优先、默认只读。** 观察工具不应该改变被观察的系统；v1 不写 Ultimate 的数据库。
2. **事件是真相，图和时间线都是投影。** 没有 append-only 的事件历史，回放和对比就做不出来。
